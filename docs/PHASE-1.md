# Phase 1 — the verified streaming loader

Status: **Gate 1 closed 2026-08-24** (local + failover legs; the live-internet leg's number
is recorded below when its run completes — the transport is the only difference).

## What was built

- `src/holo_stream.h` (~230 lines) — the browser reader's algorithm
  (`holo-apps/apps/q/core/holo-stream-load.mjs`, proven live) translated to C++:
  - **one sequential GET per origin** (curl subprocess for URLs, `fread` for local paths);
  - a **verified arrived-prefix buffer**: the fetcher appends, every completed 8 MB block is
    BLAKE3-checked against the manifest **before** its bytes become visible; readers wait on
    the verified high-water mark, never on arrival;
  - **origin failover resumes from the verified high-water only** (`Range: <hiwater>-`),
    never re-trusting bytes an earlier origin sent;
  - a `std::streambuf` over the verified prefix, handed to
    `llama_model_load_fulfill_split_future` — the seam Phase 0 probed. **Zero patches to the
    engine.**
- `tools/holo-pack.cpp` — mints the manifest: whole-file BLAKE3 (the content address,
  `holo:b3:<hex>`) + per-block BLAKE3 list. The GGUF itself is untouched — the same file
  works in every other engine, which is the point.
- `vendor/blake3/` — the reference BLAKE3 C implementation (v1.8.7), portable path.
- `tools/holo-run.cpp` — the Gate 1 binary: manifest + origins → verified stream → futures
  load → greedy generation.

## Gate 1 results (all PROVEN on this machine, 2026-08-24)

**1.1 Parity.** Streaming load through the verified path produced greedy output
byte-identical to the plain file-path baseline (" Tokyo, the largest city in the country").
All 100 blocks verified before serving; load OK at 1,143 ms (native file path: 466 ms;
the delta is the verify+copy pipeline, and it overlaps the wire on a real link).

**1.2 Tamper refusal.** One bit flipped at byte 394,276,921 (inside block 47):

```
[holo] block 47/100 FAILED verification (expected b3:9d42caec9bcf3574…,
       got b3:2da844c41bfefede…) — refusing to serve it
[   623.9ms] REFUSED: model not loaded   rc=1, stdout empty
```

The engine never saw the byte. Named block, expected/got, non-zero exit — the error taxonomy
from the surface spec, working.

**1.3 Overlap.** Carried from Phase 0's arrival-model measurement: load returns **0.66 s
after the last byte** on a simulated 50 MB/s link (wire 16.7 s). The honest framing stands:
overlap saves the load time, not the wire time; verification rides free inside the overlap.

**Failover.** Origin 1 truncated at byte 400,000,000 → automatic failover, resume at exactly
the verified high-water from origin 2, full verify, identical output.

**Live-internet leg.** First attempt failed usefully: Hugging Face 302-redirects
`resolve/main/...` to its CDN, and the fetcher's curl lacked `-L` — curl `-f` exited on the
redirect, zero bytes arrived, and the loader reported `no origin serves the remaining bytes
(verified 0/834553152)` and refused. Two lessons recorded: follow redirects (`-sL`), and the
failure mode was *honest* — nothing was served, nothing was guessed.

**Fixed run (PROVEN, real internet, 2026-08-24):** 834,553,152 bytes streamed from
`huggingface.co` over HTTPS (~6 MB/s measured link), all 100 blocks BLAKE3-verified
in-flight. `load OK` at **139,139 ms** — i.e. the wire time itself: load and verification
were fully absorbed into the stream. First token +96 ms; output identical to the local
baseline. **Cold TTFT-from-URL on this link: 139.2 s, with verification and model build
costing ~0.1 s visible.** The comparator flow (download to disk, then load) pays the same
wire plus its load serially, plus the disk round-trip.

## Deviations and debts

- **Tamper currently fails the whole stream** rather than re-fetching the bad block from the
  next origin. Correct per Gate 1.2's wording; block-granular mirror retry is Phase 2 work
  (the manifest already gives block addressing — the store makes it natural).
- Verification is in-memory only; the local store (`~/.hologram/blobs`) lands in Phase 2.
- BLAKE3 is the portable C path (no SIMD). Fine at current link speeds; measure before
  optimizing.
- The tensor-list is still generated by `tools/gen-tensor-list.py`; in Phase 2 the manifest
  carries it (their loader treats it as a strict contract — CRLF-sensitive, LF only).
